# 성능 개선 스토리라인: 3층 벽체 (ACT + 검측)

> 발표(중간발표2 11/10, 최종발표 12/8)에 쓰려고 정리한 흐름이다. 단계가 끝날 때마다 아래에 이어 쓴다.
> - 숫자는 모두 개발 시작값 700300 ~ 700399(100벽) 결과다. 최종 평가가 아니다. 최종 숫자는 설정을 고정한 뒤 시험 시작값(730000번대)으로 한 번 낸다.
> - 정책은 ACT(seed 1000, 10만 스텝)다. Diffusion은 [맨 아래](#diffusion은)에 따로 적었다.
> - 참값(시뮬레이터 정답 좌표)을 쓴 조건은 실제 로봇에서는 불가능한 진단이다. 표와 문장에 **참값 (진단)** 이라고 붙인다.

## 1단계: 셋째 벽돌부터 못 집는다 (2.08장 → 5.38장)

| | 내용 |
|---|---|
| 문제 | ACT · Diffusion 모두 벽돌 1 · 2번째는 집어 놓지만 3번째부터 헛손질만 반복했다. 검측 G1(집기 확인)이 헛집기를 잡아내도, 다시 시키면 같은 동작을 되풀이했다 |
| 원인 찾기 | 학습 장면을 그대로 넣어 보니, 어디로 갈지는 맞게 알았다. 문제는 집는 순간의 손목 각도였다. 3번째 벽돌 시연 1000개가 **505 : 495로 180° 다른 두 방향**으로 나뉘어 있었고, ACT는 둘을 평균 내 대각선으로 집게를 닫았다(20번 중 20번 헛집기) |
| 왜 두 방향이었나 | 벽돌이 180° 대칭이라 대본이 "손목을 덜 돌리는 쪽"을 고르는데, 두 쪽이 거의 동점인 자리에서는 배치 흔들림(±10°)에 따라 선택이 뒤집혔다 |
| 해결 | 대본을 고쳐 벽돌마다 손목 방향을 하나로 고정하고(1000 : 0), 1000벽을 다시 수집해 재학습했다 |
| 결과 | 3번째 벽돌 들어 올림(정책에 벽돌 하나만 맡기는 시험): **0 / 20 → 20 / 20**<br>100벽 평가(검측 포함): **2.08장 → 5.38장** |
| 배운 점 | 모방학습 성능은 정책 구조만큼 **시연의 일관성**에 좌우된다. 규칙으로 만든 시연조차 대칭 물체 · 동점 규칙 때문에 여러 갈래가 섞일 수 있다 |

## 3단계: 카메라 탓인가, 기준 자리 탓인가 (5.38장 → 8.55장)

검측(G2 · G3)의 두 가지만 바꿔 같은 100벽을 돌렸다. 정책 · 환경 · 다른 설정은 모두 같다.
- **위치 정보**: 카메라로 잰다 / 참값 (진단)으로 읽는다.
- **기준 자리**: 차례 번호 / 손에 든 벽돌의 자리.

| | 기준 자리 = 차례 번호 | 기준 자리 = 손에 든 벽돌 |
|---|---|---|
| **위치 = 카메라** | E0: 5.21장, 완성 0 | **E3: 8.55장, 완성 12** |
| **위치 = 참값 (진단)** | E1: 5.63장, 완성 0 | E2: 8.77장, 완성 11 |

| 비교 (같은 벽끼리 짝지어) | 차이 | 뜻 |
|---|---|---|
| 카메라 → 참값 (진단), 기준 = 차례 (E1 − E0) | +0.42장 | 위치를 정답으로 줘도 거의 안 오른다 → **카메라는 병목이 아니다** |
| 차례 → 손에 든 벽돌, 위치 = 참값 (진단) (E2 − E1) | +3.14장 (77벽 늘어남) | **기준 자리 어긋남이 1순위 원인**이었다 |
| 카메라 vs 참값 (진단), 기준 = 손에 든 벽돌 (E3 − E2) | −0.22장 | 참값 없이 카메라만으로 상한에 거의 닿는다 |

- **손에 든 벽돌을 어떻게 아나 (참값 없이)**: G1이 '쥐었다'고 판정한 순간, 손 위치(관절값으로 계산)에서 가장 가까운 공급칸을 고른다. 공급칸끼리는 18 ~ 26 cm 떨어져 있어서 99.5 %가 맞았다. 실제 로봇에서도 쓸 수 있는 방법이다.
- **카메라 측정 정밀도**: 손 안 벽돌 오차 중앙값 0.3 mm, 놓인 벽돌 0.2 mm.
- 숫자를 읽을 때 주의: 같은 조건을 다시 돌려도 결과가 조금씩 갈린다(10-26 대비 −0.17장, 100벽 중 40벽이 달라짐). 원인은 확인하지 못했다. 위 +3.14장은 이 흔들림보다 훨씬 크다.

## 4단계: G1 · G2 · G3는 각각 효과가 있나 (끄고 켜기)

| 조건 | 기준 = 차례 번호 | 기준 = 손에 든 벽돌 |
|---|---|---|
| 검측 없음 | 2.00장 | (같음) |
| G1만 | 4.17장 | (같음) |
| G1 + G2 | 7.41장 | 7.50장 |
| G1 + G3 | 5.91장 | 8.18장 |
| G2 + G3 | 4.14장 | 8.19장 |
| 전부 | 5.21장 | **8.55장 (완성 12)** |

- **G1(집기 확인)만 켜도 2.0 → 4.2장**: 100벽 중 90벽이 늘었다. G1은 쥐었는지 확인해 헛집기면 다시 집게 하고, 확인 뒤 정책을 다시 시작시킨다. 10-26에는 이것이 '벽돌 하나 = 동작 한 번'의 경계를 다시 세우는 효과로 해석했다(추론).
- **기준이 틀리면 검측이 오히려 해가 된다**: 차례 번호 기준에서 G1 + G2에 G3를 더하면 7.41 → 5.21장(−2.20장)으로 떨어졌다. G3가 손에 든 벽돌이 아닌 엉뚱한 자리를 검사하고 '다시 놓기' 때문으로 본다(추론).
- **기준이 맞으면 셋 다 보탬이 된다**: 손에 든 벽돌 기준에서는 G3를 더해도 떨어지지 않았고, 셋을 다 켰을 때 16장 완성이 12벽으로 가장 많았다. 다만 하나씩 뺐을 때의 차이(0.4 ~ 1.1장)는 실행 간 흔들림과 구분하기 어렵다.

## 5단계: 남은 실패는 무엇인가 (8.55장의 원인)

E3(카메라 + 손에 든 벽돌 기준)로 실패한 88벽에서, 처음 못 채운 벽돌이 어떻게 됐는지 분류했다. 실패는 2단(자리 5 ~ 10)에 몰린다.

| 처음 실패 | E3 (카메라) | E2 참값 (진단) |
|---|---|---|
| ① 차례가 오기 전에 공급대 위에서 밀리거나 엉뚱한 곳으로 옮겨짐 | **38벽** (G1 동작 중 11 · 정책 27) | 52벽 |
| ② 검측(G2 · G3)이 다루다 실패: 이웃 벽돌에 걸침 · 이웃을 밀어 떨어뜨림 | 27벽 | 12벽 |
| ③ 정책이 들고 가다 떨어뜨리거나 다른 자리에 넣음 | 17벽 | 22벽 |
| ④ 못 집음 | 6벽 | 2벽 |

- 한 자리가 실패하면, 정책은 그 뒤로 빈 공급칸만 계속 집으려 해서 벽 전체가 멈춘다.
- ①은 참값 (진단)에서도 줄지 않으므로 카메라 문제가 아니다. ②는 카메라 쪽이 두 배 넘게 많아, 카메라 측정의 작은 오차와 관련 있어 보인다(추론, 확인 안 함).

## Diffusion은

- 벽돌 하나씩 맡기면 ACT보다 잘한다(들어 올림 319 / 320, 놓기 오차도 더 작음).
- 벽 전체로는 둘째 벽돌부터 막힌다. 검측을 켜도 1.07 → 1.08장으로 그대로다.
- 원인은 벽돌 사이 이음이나 검측 뒤 정책 재시작에 있는 것으로 보이지만, 아직 진단하지 않았다(10-26 기록). 이번 개선은 ACT에만 적용해 봤다.
