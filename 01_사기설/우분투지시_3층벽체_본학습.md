# Ubuntu 작업 지시: 본 학습 (변환이 끝나면 자동 시작)

작성 2026-10-18 · 대상: Ubuntu(RTX 5090) PC에서 작업하는 코딩 에이전트 · 앞선 지시: [`우분투지시_3층벽체_2차.md`](우분투지시_3층벽체_2차.md)

1차 지시의 **1절(환경 보호 규칙), 2절(연구 원칙), 5절(멈추고 보고)**은 그대로 적용한다. 보고는 한국어로, 짧게, 표 위주로 한다. 실험설계 md는 v15 이상([`실험설계_3층벽체.md`](실험설계_3층벽체.md) 12절 "학습·평가 원칙", 7절 11·12·23번).

## 1. 할 일 한 줄 요약

**나7 변환과 검사가 끝나면 사람을 기다리지 않고** 본 데이터셋 하나로 ACT·Diffusion을 학습 seed 3개씩, 모두 6번 학습한다. 각 학습이 끝날 때마다 정상 동작만 짧게 확인한다.

---

## 2. 자동 시작 조건

- 변환이 도는 동안에는 학습을 시작하지 않는다(변환이 메모리 압박으로 한 번 멈춘 적이 있음)
- 대기 스크립트(예: `sim/wall3/train_main.sh`)를 `nohup`으로 띄워 두고, 아래가 **모두** 확인되면 바로 학습을 시작한다
  1. 나7 최종 데이터셋 `sim/data/wall3_main_<YYYYMMDD>/` 합치기 완료
  2. 다시 읽기 검사 통과: 에피소드 **16,000개**, 프레임 수가 원자료와 같음, 카메라 3대, 목표 정보 5개, 결정으로 뺀 벽(710462·710548) 없음
  3. 데이터 해시 기록 완료
- 하나라도 실패하면 학습을 시작하지 말고 멈춘 뒤 보고

## 3. 학습 설정 (6번 모두 같음, 바꾸지 않음)

| 항목 | 값 | 근거 |
|---|---|---|
| 데이터 | 위 본 데이터셋 하나 전부(벽 1,000개 = 에피소드 16,000개). 검증 분할 없음 | 설계 v6 |
| 정책 | ACT, Diffusion Policy (LeRobot 0.6.1 기본 구현, 정책 코드 수정 없음) | |

| **학습 스텝** | **두 정책 모두 100,000 스텝** | 정책끼리 같은 학습량(12절). 배치 32면 약 320만 샘플 ≈ 데이터 프레임 전체(약 330만)를 한 번 보는 양. 미니 학습 곡선은 ACT 3만, Diffusion 6만 스텝 근처에서 완만해짐(데이터 1/20). LeRobot 기본 학습 스텝도 10만 |
| 배치 | 32 | 미니 학습과 같음 |
| **행동 묶음** | **미니 학습과 같음**: ACT chunk 100·실행 100, Diffusion horizon 64·실행 32·관측 2. 미니 체크포인트의 `config.json`과 다르면 `config.json` 값을 따르고 보고 | 미니 롤아웃에서 Diffusion 멈춤 없음, ACT 실행 10은 팔이 거의 안 움직임 |
| 학습률·그 밖 | LeRobot 0.6.1 기본값 | |
| **학습 seed** | **1000, 2000, 3000** | |
| 저장 | 2만 스텝마다(이어 하기용·기록용) | |
| **쓸 체크포인트** | **마지막(10만 스텝)** | 7절 23번 권장안. 검증 분할이 없어 학습 중 고르지 않음 |
| 출력 위치 | `sim/outputs/wall3/main_train_<YYYYMMDD>/<정책>_s<seed>/` | |

## 4. 실행 순서와 속도

- 순서: **ACT s1000 → Diffusion s1000 → ACT s2000 → Diffusion s2000 → ACT s3000 → Diffusion s3000**
- 동시에 **2개씩** 돌린다(미니 학습에서 GPU 약 11 GB로 확인). 하나가 끝나면 목록의 다음 것을 시작한다. 이렇게 하면 seed 1000 두 정책이 먼저 끝난다
- **속도만 바꾸는 설정은 맨 처음 10분 안에 정해도 된다**: 데이터 로딩 작업자 수(`num_workers`), 영상 디코더(pyav / torchcodec), 동시 실행 2개 / 3개. 그 밖의 학습 설정은 바꾸지 않는다. 정한 값은 6번 모두 같게 쓰고 기록한다
- 멈춤 감시: 기존 `sim/run_v3.sh`의 `train()`처럼, 로그가 10분 넘게 조용하면 끝내고 마지막 체크포인트에서 이어 한다(최대 3번). 3번 다 실패하면 그 학습은 건너뛰고 나머지를 진행한 뒤 보고
- 예상: ACT 10만 스텝 약 4시간, Diffusion 약 3시간(미니 학습 속도 기준) → 2개씩 돌리면 **6번 모두 약 11시간**. 로딩 설정으로 빨라질 수 있음

## 5. 학습마다 정상 동작 확인 (결과로 쓰지 않음)

- 학습 하나가 끝날 때마다 마지막 체크포인트로 **정책 단독 2벽**을 돌린다
  - 환경: 동결한 `main_v1`(커밋 `482da46`의 설정)
  - 시작값: 파일럿 블록의 미사용 값 **700300 ~ 700301** (6번 모두 같은 두 값, 검증 720000번대·시험 730000번대는 사용 금지)
  - G1·G2·G3 끔, 벽돌당 17 s, 도면 순서표로 넘어감(`sim/wall3/rollout.py`)
- 기록: 들어 올린 벽돌 수, 채워진 자리 수, 벽돌별 IoU 평균, 시방 판정, 벽 하나 평가 시간, 녹화 1벽(저장소 밖)
- 학습 곡선(손실) PNG를 작게 저장

## 7. 멈추고 보고

- 2절 자동 시작 조건 중 하나라도 실패
- 학습 손실이 발산하거나(NaN, 처음보다 커짐) GPU 메모리 부족이 이어 하기로도 해결되지 않음

- G2·G3 연결(3차 작업)은 따로 지시한다. 그 작업을 함께 하더라도 학습의 CPU·GPU를 먼저 보장한다
