너는 이 Ubuntu PC(RTX 5090)에서 14조 캡스톤 저장소(github.com/wonyoungjacob/masonry-IL-capstone)의 시뮬레이션 평가를 돌린다. 중간발표용으로 아래 두 작업만 하고, 결과를 GitHub에 올린다.

## 배경 (짧게)
- MuJoCo에서 SO-ARM100이 벽돌 3개를 2+1로 쌓는 과제다. 학습 정책(ACT, Diffusion Policy) 밖에 검사 3단계를 붙인 것이 '조건 D'(실행 이름 E_replace)다.
- 작업 1: 검사가 읽는 벽돌 위치에 일부러 넣는 측정 오차(`--gate-pose-noise`, m 단위, 축마다 표준편차) 실험을 **시험 배치 50000~50049**로 다시 돌린다. 예전엔 검증 배치에서만 돌려서 기존 조건 D 시험 결과와 비교가 안 됐다.
- 작업 2: 실험 1(좁은 배치)에서 **복구 시연 없이 학습한 Diffusion(clean)** 과 **복구 시연을 섞어 학습한 Diffusion(plus2)** 을 같은 초기 배치(seed 10000)에서 재생해 영상을 만든다.

## 지켜야 할 것
- 기존 파일(코드, `sim/outputs/` 기존 결과, 데이터셋, 체크포인트)은 수정·삭제하지 않는다. 학습은 하지 않는다.
- 새로 만드는 것은 `sim/outputs/midterm1_fix/`, `sim/logs/midterm1_fix/`, 그리고 마지막에 올릴 `01_사기설/중간발표1/근거_우분투_20261012/` 뿐이다.
- 설정을 임의로 바꾸지 않는다. 막히면 우회하지 말고 멈춘 뒤 무엇이 없는지 보고한다.
- 명령은 저장소의 `sim/` 폴더에서, 파이썬은 `venv/bin/python` 으로 실행한다.

## 0. 최신 코드 받기
```bash
git pull --ff-only
ls sim/tools/render_exp1_pair.py sim/tools/noise_test_jobs.py sim/tools/summarize_noise_test.py
```
세 파일이 있어야 한다. 로컬 변경 때문에 pull이 안 되면 멈추고 `git status` 결과를 보고한다.

## 작업 1: 측정 오차 실험 (시험 배치)
```bash
cd sim
mkdir -p outputs/midterm1_fix logs/midterm1_fix
venv/bin/python tools/noise_test_jobs.py > outputs/midterm1_fix/jobs_noise.txt
cat outputs/midterm1_fix/jobs_noise.txt
```
- 표준 오류에 `# 8 jobs from outputs/final_test/jobs.py` 가 나오면 기존 조건 D 시험 명령을 그대로 복사한 것이다. `fallback` 이 나오면 기존 명령을 못 찾은 것이니, `outputs/final_test/` 에서 seed1000 모델의 E_replace 시험 명령(로그나 jobs 파일)을 찾아 같은 덩어리 구성(--seed0, --episodes 또는 --seed-list)인지 확인하고 보고한다. 추론 seed가 --seed0 에 따라 정해지므로 덩어리 구성이 같아야 비교가 맞다.
- 명령 8줄(정책 2 × σ 2·4 mm × 덩어리 2)을 확인한 뒤 실행한다.
```bash
MUJOCO_GL=egl EVAL_THREADS=1 nohup xargs -P 8 -I{} bash -c '{}' < outputs/midterm1_fix/jobs_noise.txt > logs/midterm1_fix/xargs.log 2>&1 &
```
- GPU 메모리 부족으로 죽은 작업은 `-P` 를 줄여 그 줄만 다시 돌린다. 끝나면 `outputs/midterm1_fix/*.partial` 이 남아 있지 않아야 한다.
- 집계:
```bash
venv/bin/python tools/summarize_noise_test.py
```
`outputs/midterm1_fix/summary_noise.md` 가 생긴다. σ 0 mm 가 Diffusion 30/40, ACT 26/48 로 나와야 한다. 다르면 그대로 두고 보고한다.

## 작업 2: 실험 1 clean vs plus2 영상 (작업 1과 동시에 돌려도 됨)
```bash
cd sim
ls outputs | grep -E "^diffusion_v2_2p1_joint_image_(clean|plus2)$"
MUJOCO_GL=egl venv/bin/python tools/render_exp1_pair.py diffusion_v2_2p1_joint_image_clean
MUJOCO_GL=egl venv/bin/python tools/render_exp1_pair.py diffusion_v2_2p1_joint_image_plus2
```
- 체크포인트 폴더 이름이 다르면 가장 맞는 것을 쓰고 보고한다.
- `imageio_ffmpeg` 오류가 나면 `venv/bin/pip install imageio-ffmpeg` 후 다시 실행한다.
- 각 실행 끝의 `DONE ...` 줄을 기록한다. 기대는 clean = 3개를 깔끔하게 놓음, plus2 = 다 놓은 뒤에도 집게가 오르내림. 다르면 그대로 보고한다.

## 마무리: 결과를 GitHub에 올리기
`sim/outputs/` 는 git이 무시하므로 추적되는 폴더로 복사해서 올린다.
```bash
cd ..   # 저장소 최상위
D=01_사기설/중간발표1/근거_우분투_20261012
mkdir -p "$D"
cp sim/outputs/midterm1_fix/summary_noise.md sim/outputs/midterm1_fix/jobs_noise.txt "$D"/
cp sim/outputs/midterm1_fix/test_*_s1000_D_noise*mm_*.json "$D"/
cp sim/outputs/midterm1_fix/exp1_*_seed10000.mp4 sim/outputs/midterm1_fix/exp1_*_seed10000.json "$D"/
du -sh "$D"
git add "$D"
git commit -m "중간발표 1 보강: 측정 오차 시험 배치 결과, 실험 1 clean vs plus2 영상 (Ubuntu)"
git pull --rebase
git push
```
- `git add` 는 위 폴더만 한다. 다른 파일은 올리지 않는다.
