# 선행조사: 긴 시연을 어떤 단위로 잘라 학습하는가

작성 2026-10-15 · 관련: [실험설계_3층벽체.md](실험설계_3층벽체.md) 2.1절 (벽돌 한 장 단위 학습)

**조사 방법.** 건설 분야와 일반 로봇 상위 학회(CoRL, RSS, ICRA, IROS, RA-L, ICML 등)로 나누어 조사했다. 가능한 것은 원문 PDF로 인용과 수치를 확인했고, 출판사 페이지가 막혀 초록만 읽은 논문은 "초록만"으로 표시했다. 동료심사 전 논문은 "preprint"로 표시했다. ACT·Diffusion Policy·LeRobot 기본값은 GitHub 코드로 확인했다(2026-10-15).

---

## 1. 결론

| 질문 | 답 |
|---|---|
| 벽돌 한 장 = 에피소드 1개(B안)에 선례가 있나 | 있다. 건설 분야 모방학습은 거의 모두 **요소 하나(벽돌·타일·목재 이음·철근 매듭)를 에피소드 하나**로 쓴다 |
| 다음 요소는 누가 정하나 | 거의 모두 **정책 밖**: 설계 도면, BIM, 기호 계획기, 정렬 규칙, 사람 |
| 긴 시연을 무슨 기준으로 자르나 | 일반 로봇 학회의 주류는 **물체 하나 단위의 사건 경계**(잡았다, 놓았다, 아래 블록에 얹혔다). 시뮬레이터 상태로 **수집 후 자동으로** 잘라도 된다(MimicGen). 건설 분야는 처음부터 요소 하나씩 수집하는 경우가 많다 |
| 쪼개는 게 통째보다 나은가 | 건설 분야에는 직접 비교가 없다. 일반 분야에서는 같은 데이터로 쪼갠 쪽이 크게 나았다(HITL-TAMP, BUDS) |
| 우리 조합이 이미 있나 | 찾지 못했다: ACT·Diffusion Policy + 벽 시연을 벽돌 단위로 자름 + 목표 입력 + 도면 순서 + 벽돌별 정책 밖 검측 |

## 2. 가장 가까운 연구

| | BrickCraft (Yu et al. 2026, arXiv:2605.07605, preprint) · BrickCraft-Duo (arXiv:2609.28281, preprint) | Liu W. et al. 2026 (arXiv:2605.13754, preprint) |
|---|---|---|
| 과제 | 실제 로봇(Kinova Gen3 + Robotiq 2F-85), 레고 듀플로 인터로킹 벽돌 조립. 시연 865개, 조립 기술 7개 | **벽돌 3단 벽**(12장, 시뮬레이션 36장), 천장 타일. Franka Panda |
| 에피소드 단위 | 조립 한 단계 = 벽돌 한 장. Duo: "각 시연은 전체 조립 순서가 아니라 조립 한 단계에 해당" | 벽돌 한 장. "벽 전체가 아니라 요소 작업 하나만 시연하면 된다" |
| 학습 범위 | Diffusion Policy는 **끼우는 동작만**. 집기·이동은 정해진 동작 | 신경망 아님(시연 하나로 경로 계획) |
| 목표 입력 | 기준 벽돌에 대한 상대 위치 등 정수 6개 + 예상 완성 모습 마스크 | **벽돌 번호·줄·단과 벽돌 치수로 계산한 목표 좌표** |
| 순서 | 기호 계획기(분해 순서를 거꾸로) | 벽 설계 명세 |
| 검측 | 집기 후 "안정적 쥠", 조립 후 예상 모습과 IoU 비교 | 없음 |
| 결과 | 한 단계 성공 86.25%(240회), 긴 과제 7개 모두 완성률 80% 이상. Duo: 단계별 사람 교정 후 9단계 구조 0/5 → 4/5 | 실제 시험 전부 성공 |
| 우리와 다른 점 | 끼우기만 학습, 상대 코드, 레고·실기, 자동 재배치 없음 | 학습 정책 아님 |

## 3. 건설 분야

| 논문 | 에피소드 단위 | 자르는 기준 | 목표 입력 | 순서 |
|---|---|---|---|---|
| BrickCraft / Duo (2026, preprint) | 벽돌 한 장 | 처음부터 한 단계씩 수집 | 단계별 정수 코드 + 마스크 | 계획기 |
| Liu W. et al. (2026, preprint) | 벽돌 한 장 | 한 장 시연을 일정 나사 운동 구간으로 자동 분할 | 단·줄·번호로 계산한 목표 자세 | 벽 명세 |
| Ibrahimov, Mozaffari, Adel (2026, preprint, arXiv:2608.22100) | 목재 이음 하나(정책 3개) | 처음부터 이음별 생성(접근 + 끼우기) | 없음(목표 고정) | 고정 스크립트 |
| Yu, Kamat, Menassa (2024, J. Comput. Civ. Eng. 38(4), doi:10.1061/JCCEE5.CPENG-5731) | 타일 한 장 안의 동작 8개 | k-평균 군집 + 숙련공이 이름 붙임 | BIM 목표 | GRU가 동작 순서 학습 |
| Hu, Yu, Chandramouli, Liang (2026, J. Comput. Civ. Eng. 40(6), doi:10.1061/JCCEE5.CPENG-7696) | 패널 한 장(집기 / 설치) | 명시 없음 | 언어 또는 물체 상태 | 해당 없음 |
| Wang X. et al. (2023, Autom. Constr. 155, doi:10.1016/j.autcon.2023.105071) | 동작 단위 | 처음부터 동작을 골라 시연해 자르기를 피함 | BIM | 장면 상태로 다음 동작 학습 |
| Liang et al. (2022, J. Comput. Civ. Eng. 36(2), doi:10.1061/(ASCE)CP.1943-5487.0001004) | 타일 한 장 | 자르지 않음 | 목표 격자 | 사람 |
| Kramberger et al. (2022, Front. Robot. AI 8, doi:10.3389/frobt.2021.768038) | 목재 이음 하나 | 명시 없음 | 설계자가 준 목표 자세 | 설계 파이프라인 |
| Mozaffari et al. (2025, preprint, arXiv:2511.17774) | 끼우기만 | 계획기가 끼우기 직전 자세까지 이동 | | |
| Wang Z. et al. (2025, preprint, arXiv:2509.00065) | 철근 매듭 하나 | 매듭별 점구름 조각 | | 좌표 정렬 규칙 |
| Huang et al. (2027, J. Comput. Civ. Eng. 41(1), doi:10.1061/JCCEE5.CPENG-7917) **초록만** | 미확인 | 성공 에피소드만 남김 | 언어 | VLM이 행동 제안 |
| Sun T. et al. (2026, Autom. Constr. 181, doi:10.1016/j.autcon.2025.106671) **초록만** | 미확인 | | | |

- 처음부터 요소 하나씩 수집하는 경우가 많고, 여러 요소를 담은 긴 시연을 집게 개폐 등으로 나중에 자른 건설 논문은 찾지 못했다.
- 학습 부분은 놓기·끼우기만이고 집기·이동은 정해진 동작인 경우가 많다.

## 4. 일반 로봇 상위 학회

| 자르는 기준 | 논문 | 핵심 근거 |
|---|---|---|
| 물체 하나 단위 사건 경계 | MimicGen (Mandlekar et al., CoRL 2023, arXiv:2310.17596) | 블록 3개 쌓기에서 "손가락이 블록에 닿으면 잡기 끝, 블록이 들렸다가 아래 블록과 닿으면 놓기 끝". "이 판정은 시연을 자를 때만 쓰고 정책 실행 중에는 쓰지 않는다." 단, MimicGen 자체는 자른 조각을 데이터 생성에만 쓰고 정책은 통째로 학습 |
| 〃 + 정책 밖 계획기가 순서 | HITL-TAMP (Mandlekar et al., CoRL 2023, arXiv:2310.16014) | **같은 시연 200개로** 통째 실행 vs 계획기가 구간만 맡김: Square 82.0 → 100%, Square Broad 15.3 → 94.7%, Three Piece Assembly 75.3 → 77.3%, Tool Hang 67.3 → 82.0% |
| 〃 + 요소마다 시작·종료 조건 | SkillMimicGen (Garrett et al., CoRL 2024, arXiv:2410.18907) | 구간 정책 72.6 ~ 85.7% vs 통째 학습 59.1% (데이터 생성 방식이 달라 직접 비교는 아님) |
| 정책 밖 순서 + 단계마다 목표 입력 | CLIPort (Shridhar et al., CoRL 2021, arXiv:2109.12098) | 블록 피라미드를 정해진 순서로: 단계 목표 없음 4.5% vs 단계 목표 98.8% (시연 1,000개) |
| 정책 밖 순서 + 성공 확인 후 다음 | CALVIN (Mees et al., RA-L 2022, arXiv:2112.03227) | 현재 과제가 완료로 판정될 때만 다음 지시로 넘어감 |
| 비지도 기술 발견 | BUDS (Zhu et al., RA-L 2022, arXiv:2109.13841) | 순수 모방학습, Kitchen: 통째 24.4% vs 쪼갬 72.0%. 기술 1개면 0%, 6개 72.0%, 11개 44.6% → 쪼개는 정도가 중요 |
| 한 부품 = 한 구간, 끝나면 초기 자세 복귀 | T-STAR (Lee et al., CoRL 2021, arXiv:2111.07999) | "다음 기술로 넘어갈 때 로봇 상태 차이를 줄인다" → 철수 단계의 근거. GAIL+PPO라 순수 모방학습은 아님 |
| 언어 하위 과제 + 상위 VLM | Hi Robot (Shi et al., ICML 2025, arXiv:2502.19417) | 1 ~ 3초 기술로 잘라 언어로 지시 |
| 키프레임(구간 안 단축) | Q-attention (James & Davison, RA-L 2022), PerAct (CoRL 2022), AWE (Shi et al., CoRL 2023) | 집게 상태 변화 + 속도 0 근처를 키프레임으로. 에피소드를 자르는 기준이 아니라 구간 안을 줄이는 기준 |
| 반례: 통째 학습 | ACT (RSS 2023), Mobile ALOHA (CoRL 2024), Diffusion Policy (RSS 2023), robomimic (CoRL 2021), LIBERO-Long (NeurIPS 2023) | 한 과제 정책은 통째 학습이 기본. 하위 과제는 평가 때만 나눔 |
| 목표 형식 | RT-H (Belkhale et al., RSS 2024, arXiv:2403.01823) | 숫자 원핫 라벨이 언어보다 크게 나빴음(범용 다중 과제 환경) |

## 5. 검증용 시연이 필요한가

| 근거 | 내용 |
|---|---|
| robomimic (CoRL 2021) | 검증 손실이 가장 낮은 체크포인트는 최고 체크포인트보다 크게 나쁨. Square 80.7% vs 2.7%, Transport 64.0% vs 0.7%. "검증 손실은 정책 성능의 나쁜 척도" |
| SIMPLER (Li et al., CoRL 2024, arXiv:2405.05941) | "모방학습에서 검증 오차는 실제 성능의 좋은 대리 지표가 아니다" |
| ACT 코드 | 시연 80/20 분할, 검증 손실 최저 체크포인트 저장 |
| Diffusion Policy 코드 | 시뮬레이션: 실제 실행 점수로 상위 5개 보관. 실기: 정해진 학습량 후 마지막 체크포인트 |
| LeRobot 코드 | 기본 검증 없음(v0.6.0에 선택 기능 추가, 기본 꺼짐). 정해진 스텝 학습 후 저장 |

결론: 검증용 시연은 두지 않는다. 체크포인트는 검증 손실이 아니라 미리 정한 규칙(마지막 체크포인트 또는 검증 배치 실행 성공률)으로 고른다.

## 6. 우리 설계에 반영한 것 (실험설계 v6)

| 항목 | 반영 |
|---|---|
| 자르는 방법 | 대본이 벽돌마다 시작·끝 스텝을 기록하고 그 표시로 자름. 시작 = 철수 자세에서 출발, 끝 = 벽돌이 받침에 얹히고 집게가 철수 자세로 복귀 (MimicGen, T-STAR) |
| 학습 범위 | 집기 ~ 철수 전부 학습. 집기를 대본이 하면 G1(집기 확인)을 시험할 의미가 없음 |
| 목표 입력 | 도면에서 계산한 목표 좌표 + 온장/반장 (CLIPort, Liu, RT-H) |
| 순서표 진행 규칙 | 성공 확인 없이 정해진 규칙으로 넘어감. 순서표가 성공을 확인하면 숨은 검측이 되어 8조건 비교가 오염됨 (CALVIN과 다르게 하는 이유) |
| 검증용 시연 | 두지 않음 (robomimic, SIMPLER, LeRobot) |
| 데이터 처리 | LeRobot은 에피소드 경계에서 행동 묶음을 잘라냄 → 행동 묶음이 두 벽돌에 걸치지 않음 |
