## 1. 지킬 규칙

- 답과 문서는 한국어로, 짧게, 표 위주로 쓴다. 사실과 추론을 나눠 쓴다. 속도보다 오류 없는 것이 먼저다.
- **묻고 기다리지 않는다.** 판단이 필요하면 이 문서의 기준을 따르고, 기준이 없으면 보수적인 쪽(빼기, 탈락, 멈춤)을 골라 보고서의 '스스로 정한 것'에 적는다.
- 기준과 후보는 결과를 보기 전에 파일로 확정해 커밋한다. 결과를 본 뒤 기준을 바꾸지 않는다. 바꿔야 하면 바꾸지 말고 보고한다.
- 사기설 것을 건드리지 않는다.
  - 수정 금지: `01_사기설/실험설계_3층벽체.md`, `01_사기설/평가지표_3층벽체_20261013.md`, `01_사기설/계획서/`, `sim/brick_sim/*`, `sim/collect.py`, `sim/eval_policy.py`, `sim/tools/*`.

  - 사기설용 시작값(700000번대 ~ 730000번대)은 쓰지 않는다.
- 출력 폴더와 파일은 덮어쓰지 않는다. `sim/data` · `sim/outputs` · `sim/logs`는 커밋하지 않는다.

- **외부 업로드 금지**(Hugging Face 포함). 파일 공유는 이 저장소로만 한다.
- `sim/venv`에 pip로 설치하지 않는다. 새 패키지가 필요하면 멈추고 보고한다(6단계의 VLA 환경만 별도 venv 허용).
- 숫자는 기록(파일)에서 확인한 것만 쓴다. 시각은 `date`로 잰다.

## 4. 자원 한도 (컴퓨터가 멈추지 않게)

과거 기록(`01_사기설/근거_우분투_wall3_본학습/경위.md`)의 사실: 학습 2개를 동시에 돌리다 메모리 부족으로 컴퓨터가 멈춰 재부팅했다. 데이터 로딩 작업자의 메모리가 시간이 갈수록 불어났다. 데이터 디스크가 회전식 HDD라 캐시가 밀리면 속도가 1/10로 떨어졌다. 업로드와 학습이 겹쳐 종료된 적이 있다.

### 4.1 0단계에서 재서 기록할 것

`free -g`(전체 · 사용 가능 · 스왑), `nproc`, `nvidia-smi`(전체 · 사용 중 VRAM, 다른 프로세스), `df -h`(출력 · 데이터 디스크 남은 용량), 절전 설정, `loginctl show-user $USER -p Linger`.

### 4.2 한도

| 항목 | 규칙 |
|---|---|
| GPU 작업 | **한 번에 하나.** 학습과 평가를 겹치지 않는다. 다른 프로세스가 GPU를 쓰고 있으면 건드리지 말고 끝날 때까지 기다린다 |
| 학습의 RAM | 학습마다 별도 `systemd-run --user --scope`로 띄우고 `MemoryMax = min(전체 RAM × 0.6, 전체 RAM − 12 GB)`, `MemorySwapMax = 2G`, `nice 10`. 한도를 넘으면 그 학습만 죽고 컴퓨터는 살아 있게 한다 |
| 데이터 로딩 | 작업자 4개로 시작(과거 8개에서 메모리가 불어남). 속도가 모자라도 6개를 넘기지 않는다 |
| 학습 나눠 돌리기 | 2만 스텝마다 체크포인트를 저장하고 프로세스를 끝낸 뒤 그 체크포인트에서 이어 한다(작업자 메모리 누적 방지). 감시 스크립트는 죽은 학습을 마지막 체크포인트에서 최대 3번 이어 한다 |
| VRAM | 본 학습 전에 같은 설정으로 200스텝을 돌려 최고 사용량을 기록한다. 26 GB를 넘으면 배치를 반으로 줄이고 기록한다. 32 GB 중 4 GB 이상을 비워 둔다 |
| 평가 병렬 수 | 프로세스 1개의 RAM · VRAM을 먼저 재고, `P = min(8, (사용 가능 RAM − 12 GB) ÷ 프로세스당 RAM, (남은 VRAM − 4 GB) ÷ 프로세스당 VRAM)`로 정한다 |
| 평가의 RAM | 평가 묶음도 scope로 띄우고 `MemoryMax = 전체 RAM × 0.5` |
| 디스크 | 수집 전에 필요 용량을 스모크(벽 2개)로 추정한다. 남은 용량의 50 %를 넘으면 시연 수를 줄이고 기록한다. 남은 용량이 50 GB 아래로 내려가면 멈춘다 |
| 캐시 예열 | 데이터셋이 전체 RAM의 40 % 이하일 때만 학습 전에 한 번 읽는다. 그보다 크면 예열하지 않는다 |
| 동시 작업 | 학습 중에는 수집 · 변환 · 대용량 복사를 돌리지 않는다 |
| 절전 | AC 전원 자동 절전을 끈다. 긴 작업은 세션과 분리된 사용자 서비스로 띄우고 linger가 꺼져 있으면 켠다(`loginctl enable-linger`) |
| 감독 | 긴 계산은 `wall3.supervisor`와 같은 방식(끝남은 결과 파일로 판정, 죽으면 `_STOPPED_n`으로 이름만 바꾸고 다시, 최대 2번)으로 돌린다. 부분 결과는 합치지 않는다 |
| 메모리 감시 | 학습 · 평가 중 5분마다 사용 가능 RAM을 로그에 남긴다. 사용 가능 RAM이 6 GB 아래로 10분 넘게 머물면 그 작업을 체크포인트에서 다시 시작한다 |

## 5. 1단계: 환경

### 5.1 건식 환경 (모르타르 없음)

| 항목 | 정의 |
|---|---|
| 모르타르 | 없음. 모르타르 판, 경화 고정, 줄눈 모델을 모두 쓰지 않는다 |
| 위아래 | 벽돌 위에 벽돌을 바로 놓는다. 단 높이 = 벽돌 두께 57 mm. 1단은 바닥에 바로 놓는다 |
| 옆 간격 | 설계 간격 10 mm를 **빈 틈으로** 둔다(가로 좌표는 기존과 같음). 이유: 벽돌 치수 편차 축을 넣으려면 옆 여유가 필요함. 윈도우 세션이 정한 기본값이며 사용자가 바꿀 수 있음 |
| 놓인 벽돌 | 마찰로만 서 있다. 부딪히면 움직인다 |
| 그 밖 | 로봇, 집게, 공급대, 흩어짐(±10 mm · ±10°), 제어 주기, 벽돌당 시간 제한은 main_v1과 같게 |
| 시방 판정 | ② 선 및 면 · ③ 수직도 · ④ 평면상 위치 6 mm, ⑤ 벽 두께. ① 가로줄눈은 평가하지 않는다. 설계 높이는 건식 기준으로 다시 계산한다 |

환경 버전 이름을 새로 붙이고(예: `dry_v1`) 설정 전체와 해시를 결과에 저장한다.

### 5.2 장 단위 시험

[사실] 기존 정책은 이미 벽돌 한 장 = 에피소드 1개로 학습하고, 목표 정보(도면 목표 x · y · z · yaw + 반장)를 입력으로 받는다. 새로 만드는 것은 **평가 방식**이다.

| 평가 | 정의 |
|---|---|
| 장 단위 (독립 시행) | 자리 k보다 앞선 벽돌을 설계 위치에 미리 놓은 장면에서 벽돌 k 한 장만 수행. 16자리 × 장면 수. 앞 자리의 실패가 뒤로 번지지 않음 |
| 벽 단위 (연쇄) | 빈 바닥에서 16장을 차례로 수행 |

장 단위에서 기록할 것: 채움 여부, 설계 대비 자세 오차(수평 mm, 높이 mm, 회전 °), 이미 놓인 벽돌이 밀린 최대 거리, 걸린 시간, 실패 종류.

### 5.3 통과 기준

정답 좌표를 쓰는 대본으로 건식 환경에서 50벽(800100 ~ 800149)을 쌓아 **시방 합격 45벽 이상**. 미달이면 원인을 기록하고 대본의 놓기 동작만 고친다(하루 한도). 그래도 미달이면 멈추고 보고한다. 과제 자체가 성립하지 않는다는 뜻이기 때문이다.

## 6. 2 ~ 4단계: 카메라 세팅 선정

근거 문헌과 이유는 아이디어 md 7절에 있다. 여기에는 실행에 필요한 것만 적는다.

### 6.1 공통 규칙

| 항목 | 규칙 | 근거 |
|---|---|---|
| 세팅 하나 | 고정 카메라 + 손목 카메라, **정책에 넣는 영상은 최대 3장** | 공개된 π0 · π0.5는 영상 자리 3개. 카메라를 다 넣은 구성이 상위에 든 적이 없다는 보고 |
| 손목 카메라 | 항상 포함 | 손목 영상을 빼면 성공률이 크게 떨어진다는 보고 다수 |
| 원본 영상 | 카메라마다 1280 × 960 색 + 깊이. 세 방식이 같은 카메라를 쓴다 | 공정성 |
| 정책 입력 | 원본 색 영상을 비율을 유지해 줄이고 여백을 채운 224 × 224. ACT와 VLA가 같은 입력을 받는다 | π0.5 · OpenVLA 계열의 입력 크기 |
| 규칙 기반 입력 | 같은 카메라의 원본 색 + 깊이 | – |
| 깊이 잡음 | 깊이에 거리의 제곱에 비례하는 잡음을 넣는다: σ = z² × 시차 잡음 ÷ (초점거리 × 기선). 고정 카메라는 D435급(기선 50 mm, 범위 0.3 ~ 3 m), 손목은 D405급(범위 7 ~ 50 cm). 범위 밖은 무효. 쓴 값과 출처를 설정에 저장한다 | 제조사 자료. 잡음 없는 깊이는 규칙 기반에 유리한 가정 |
| 카메라 자세 | 학습 · 평가 · 세 방식 모두 완전히 같게 고정 | 카메라 자세가 바뀌면 성공률이 크게 떨어진다는 보고 |

### 6.2 카메라 위치 후보 (2단계에서 전부 지표를 잰다)

좌표는 세계 좌표(m)다. 원점은 로봇 받침대 아래 바닥 중심, 벽 중심선 y = +0.60, 공급대 y = −1.00 ~ −0.17(윗면 높이 0.35). 팔이 지나는 부피와 겹치면 가장 가까운 겹치지 않는 위치로 옮기고 기록한다.

### 6.3 기하 지표 (2단계, 학습 없음)

대본 궤적 20벽(800000 ~ 800019, 320장)을 재생하면서 후보 카메라마다 분할 영상(물체별 화소 표시)을 5스텝마다 그려 계산한다.

| 지표 | 정의 |
|---|---|
| 정적 포함 | 공급 16칸 윗면과 놓을 자리 16곳이 팔이 철수 자세일 때 영상 가운데 90 % 안에 들어오는 비율 |
| 가림 | 구간(집기 접근, 집기, 운반, 놓기 접근, 놓기)마다, 대상(집을 벽돌 / 놓을 자리 / 든 벽돌 / 손끝)이 가리지 않았을 때의 화소 중 실제로 보이는 비율. 구간별 중앙값과 50 % 미만인 프레임 비율 |
| 화소 크기 | 224 영상에서 벽돌 90 mm 변이 차지하는 화소 수(가장 먼 대상 기준). 원본 영상의 mm/화소 |
| 입사각 | 벽돌 윗면에 대한 시선 각도(최대값) |
| 깊이 잡음 예측 | 작업 거리에서의 σ (6.1 식) |

2단계의 산출물: 후보 전체의 지표 표, 카메라별 예시 영상 모음 그림, 아래 6.4의 세팅 6개의 확정 좌표. **이것을 커밋한 뒤에 3단계로 간다.**

### 6.4 세팅 후보 (6개, 구성 규칙은 미리 고정)

| 세팅 | 구성 | 뜻 |
|---|---|---|
| R0 | WB1 + WA1 + H0 | 지금 세팅(대조). 공급대를 보는 고정 카메라 없음 |
| RA | SA 중 최선 + WA 중 최선 + 손목 최선 | 영역마다 수직 |
| RB | SB 중 최선 + WC 중 최선 + 손목 최선 | 로봇 맞은편에서 비스듬히 |
| RC | SA 중 최선 + WC 중 최선 + 손목 최선 | 혼합 |
| RD | SB 중 최선 + (WD1, WE1 중 최선) + 손목 최선 | 벽을 옆 · 대각에서 |

- '최선'은 같은 계열 안에서 **집기 접근 · 놓기 접근 구간의 가림 지표(50 % 미만 프레임 비율)가 가장 낮은 것**. 같으면 원본 mm/화소가 작은 것.
- 손목 최선은 H0 · H1 · H2 중 (집기 접근에서 집을 벽돌, 놓기 접근에서 놓을 자리)의 보이는 비율 중앙값의 합이 가장 큰 것.
- SC1 · SD1은 지표 표에만 넣는다(세팅에는 쓰지 않음).

### 6.5 측정 오차 (3단계)

세팅마다 `wall3/perception.py`의 방식을 그 세팅의 카메라로 옮겨, 정답 좌표 없이 벽돌 자세를 잰다. 깊이 잡음을 넣은 상태로 잰다. 장면은 820000 ~ 820099.

### 6.6 정책 선별 (4단계)

### 6.7 선정 규칙 (미리 고정)

1. **필수 조건.** 하나라도 어기면 탈락으로 표시한다.
   - 정적 포함 100 %.
   - 집기 접근 · 놓기 접근 구간에서 대상이 **모든** 영상에서 50 % 미만으로 보이는 프레임이 5 % 이하.
   - 측정 오차: 공급대 벽돌과 놓인 벽돌의 수평 오차 95백분위 2 mm 이하(허용오차 6 mm의 1/3), 못 잰 비율 2 % 이하.
2. **순위.** 필수 조건을 통과한 세팅을 ACT 장당 성공률로 줄 세운다(장면 단위 부트스트랩 95 % 구간 포함).
3. **동률.** 1위와 구간이 겹치는 세팅끼리는 가림 지표가 낮은 쪽, 그래도 같으면 영상 수가 적은 쪽을 고른다.
4. 통과한 세팅이 없으면 기준을 낮추지 말고, 가장 가까운 세팅과 미달 항목을 보고하고 멈춘다.
5. R0가 가장 좋게 나와도 그대로 보고한다. 다만 R0는 공급대를 보는 고정 카메라가 없어 필수 조건에서 탈락할 것으로 예상한다(예상이며 결과로 확인).

주의(보고서에 적을 한계): 선별에 ACT만 썼으므로 선정이 ACT 쪽으로 기울 수 있다. 영상 3장 · 224 · 외부 + 손목 구성으로 VLA의 입력 관행을 맞춘 것이 그 대응이다.
