### 2.5.6 시연 생성 — IK 스크립트 전문가 (v5의 변경 핵심)

**결정.** 사람이 리더암으로 시연하지 않는다. 시뮬레이터는 모든 벽돌의 정확한 자세를 알고 있으므로, 집기·놓기 경로점을 벽돌 자세에 상대적으로 정의하고 역기구학(IK)으로 관절 각도 목표로 변환하는 **스크립트 전문가**가 시연을 생성한다. 벽돌 치수·공급 위치·자세를 매 에피소드 랜덤화해 규모를 키우고, 성공한 에피소드만 데이터셋에 남긴다.

**왜 이것이 표준 관행인가.**

- 로봇 학습 벤치마크의 시연은 대부분 플래너가 만든다. RLBench는 "과제 생성 시 지정한 경로점 위에서 모션 플래너가 동작하므로 **시연이 무한히 공급된다**"고 명시하고 [135], ManiSkill2/3는 모션 플래닝 해법을 공개해 시연을 생성하며 PickCube·StackCube가 그 최소 원형이다 [136]. Ravens/Transporter Networks는 스크립트 오라클 시연만으로 블록 적층·팔레타이징을 학습했고, 시연 1→10→100→1,000개에서 피라미드 적층 성공률이 13→43→56→78%로 올랐다 [68]. 실물 대규모 데이터셋 BridgeData V2도 픽앤플레이스 9,731개는 스크립트 정책으로 자동 수집했다 [145].
- **같은 과제·같은 개수에서 스크립트 시연이 사람 시연보다 학습이 쉽다.** ACT 논문의 시뮬레이션 실험은 각 50개 시연으로 Cube Transfer **스크립트 86% 대 사람 50%**, Bimanual Insertion **32% 대 20%**를 보고했고, "사람 시연의 확률성과 다봉성이 모방학습을 훨씬 어렵게 만든다"고 적었다 [11]. LeRobot 허브에 같은 스크립트 데이터셋이 공개되어 있어 재현 가능하다.
- **행동 일관성이 상태 다양성보다 중요하다.** Belkhale 등은 "고품질 데이터셋은 정책이 시험 시 분포 안에 머물게 한다"며 행동 발산과 전이 다양성을 품질 척도로 제시했고, 상태 다양성이 항상 유익하지는 않다고 보고했다 [24]. IK 전문가는 행동 일관성이 극대화된 전문가다.
- **생성 시연을 늘리면 사람 시연을 능가한다.** RoboCasa는 사람 시연 50개(28.8%)보다 생성 시연 3,000개(47.6%)가 높았다고 보고했다 [141]. Optimus는 과제당 1,000개의 TAMP 시연으로 시각 정책 70~80%를 얻었다 [139].
- **건설 도메인의 직접 선례.** Ibrahimov 등(Princeton, 2026)은 "각 과제에 대해 시뮬레이션에서 시연 1,000개를 수집"했고 "고정 회전의 Cartesian 궤적을 **미분 역기구학 컨트롤러**로 추종해 매 제어 주기 관절 위치 목표를 출력"했으며, 시작 위치 랜덤화와 진폭 2 mm의 대역 제한 외란을 넣어 Diffusion Policy를 학습했다. 결과는 실물 zero-shot 목재 장부맞춤 100%, 파이프 100%, 트러스 90~100%였다 [130]. 본 계획의 레시피와 거의 같다.

**알려진 함정과 대응.**

| 함정 | 근거 | 대응(출처) |
|---|---|---|
| 복구 행동이 없어 분포 밖에서 오차가 누적된다 | DAgger의 covariate shift [25]; "복합 오차로 정책이 복구할 수 없는 상태로 간다" [24] | **DART**: 수집 중 실행에 노이즈를 주입하고 라벨은 깨끗한 전문가 행동으로 남겨 복구 데이터를 만든다 [138]. MimicGen도 action_noise 0.05를 기본으로 쓴다 [76]. 재시도 구간을 데이터에 남기면 정책이 복구를 배운다 [142] |
| 행동이 단봉·과도하게 매끄러워 다양성이 부족하다 | 사람 시연의 다봉성 [11] | 다양성은 **상태 측**(벽돌 치수·공급 위치·자세·파지 각) 랜덤화로 확보 [24]; 과제 인스턴스 수를 늘리는 것이 일반화에 유리 [143] |
| 타이밍이 정책 제어 주기와 다르다 | Optimus의 궤적 길이 이상치 제거 [139]; Ibrahimov의 10 Hz 다운샘플 [130] | 시연을 정책 제어 주기(25 Hz)로 생성·기록, 길이 이상치 제거 |
| 전문가가 특권 상태(정확한 물체 자세)를 쓴다 | "TAMP는 학습자가 쓸 수 없는 정보로 동작한다" [139] | 시뮬레이션이므로 허용. 영상 정책의 관측에는 자세를 넣지 않는다(1.9절). 좌표 정책은 특권 기준선 |
| IK 특이점·관절 한계·충돌 | Isaac Lab DLS 문서 [140]; ManiSkill "단순 과제에만" [136] | 감쇠 최소자승(DLS) IK [146], 관절 한계 클리핑, **도달 가능 영역 사전 맵**으로 벽·공급기 배치, 베이스 근처 도달 불가 구역을 피하는 호(polar) 경로 |
| 스크립트 시연으로 학습한 영상 정책의 일반화 | 긍정: ACT 86% [11], Optimus 70~80% [139], RoboCasa [141]. 부정: ManiSkill2 순수 BC PickCube 1% [136] | 시각 도메인 랜덤화, 성공 에피소드만 보존, 과제당 1,000개 이상 |

**생성 레시피(본 팀 구현).**

1. 프리미티브: 사전 파지(위 40 mm) → 하강 → 파지 → 들기 → 운반(로봇 베이스 기준 극좌표 보간, 도달 불가 구역 회피) → 하강 → **서보 보정**(시뮬레이터가 주는 TCP 오차를 명령에 적분해 정상상태 오차 제거) → 해제 → 후퇴. ManiSkill StackCube 해법의 구조에 서보 보정과 후퇴를 더한 것이다 [136].
2. IK: MuJoCo `mj_jacSite` 야코비안으로 감쇠 최소자승(λ=0.05) 반복 [146]. 5자유도 SO-ARM100은 "그리퍼가 아래를 향한다"는 제약이 1차원이라 위치 3 + 방향 3의 과제가 5관절에서 일관되게 풀린다.
3. 벽돌 공급: 그리드 대신 **단일 공급 슬롯**에 한 장씩 놓는 공급기(feeder) 모델. Hadrian X와 SAM이 실제로 쓰는 방식이며 [111], 그리드 배치에서 열린 그리퍼가 이웃 벽돌과 충돌하는 문제를 없앤다.
4. 랜덤화: 벽돌 치수 ±5%, 공급 위치 ±10 mm, 공급 자세 ±5°. 노이즈 주입(DART) 유/무를 데이터셋 변수로 둔다.
5. 기록: 25 Hz, 손목·전면 카메라 128×128, 관절 상태 6, 벽돌 절대 자세(좌표 정책용 `observation.environment_state`), 깨끗한 관절 위치 목표 6. LeRobot v3 데이터셋 형식.
6. 필터링: 정착 후 8종 지표를 계산해 안정(붕괴 0)이고 배치 성공률 ≥ 0.5인 에피소드만 보존, 에피소드별 지표를 함께 저장.
