### 0.3 사용자가 없을 때의 원칙

아래는 우분투 쪽이 사용자 말(0.1 "내가 자리 비워도 윈도우에서 시작하는 시스템")을 풀어 쓴 것이다. 사용자가 직접 정한 문장은 아니다.

- **묻고 기다리지 않는다.** 판단이 필요하면 내용을 가장 덜 바꾸는 쪽을 고르고 계속한다. 고른 것과 이유는 새 설명 md의 '스스로 정한 것 · 사용자 확인 필요' 표와 마지막 보고에 적는다.
- **멈추는 경우는 셋뿐이다.** 그 부분만 남기고 나머지는 계속한다.
  1. 인증 · 토큰이 필요하다(`git push`가 안 되는 경우 포함). 토큰을 찾거나 묻지 않는다. 커밋까지만 하고 알린다.
  2. 기존 파일을 지우거나 덮어써야 한다.
  3. 13.4의 '바꾸면 안 되는 것'을 어겨야만 형식을 맞출 수 있다.
- 사용자가 돌아와서 한 말이 이 문서와 다르면 사용자 말이 먼저다. 그 내용을 5.1 표에 덧붙인다.

  2. **학회 양식 `ksarc-포스터 PPT 양식.pptx`를 `02_KSARC2026/`에 같은 이름으로 둔다.** 이 파일은 git에 없다(사용자 파일이라 커밋하지 않음). 스크립트는 이 파일을 복사해 `ppt/slides/slide1.xml`만 새로 짜고, 절 제목은 양식의 도형 '직사각형 18'을 복제한다. 양식이 없으면 스크립트로는 만들 수 없다. 그때는 13.3의 (가)로 한다.
  3. 다음을 실행한다.
     ```powershell
     cd sim
     $env:PYTHONUTF8 = "1"            # 파일 읽기와 화면 출력을 UTF-8로 (윈도우 기본 cp949에서 한글이 깨지는 것을 막음)
     $env:PYTHONPATH = "."
     $env:WALL3_OUT = (Resolve-Path "..\02_KSARC2026\원자료_포스터d_20261111\wall3").Path

     $env:PYTHONPATH = ".;tests"; python -m unittest test_primary_metrics_20261111            # 점검: 테스트 8개 OK
     ```
  - 임시 폴더에 만든 그림 6장을 `02_KSARC2026/포스터_초안_20261111e_그림/`과 비교한다. sha256 앞 16자리(우분투):
    `그림1` ec6fa3e49215177e · `그림2` 8abcb3741cb60f38 · `그림3` 711cc8d28e3c8cb4 · `그림4` c3802fa816b6649a · `그림5` 611b5d0eeba076a4 · `그림6` b03bf7a7c9b86779.

## 2. 작업 규칙 (사용자 지시, 계속 유효)

- 답은 한국어로, 짧게, 표 위주로 쓴다. 사실 · 해석 · 추론을 나눠 쓴다. 성급한 가설과 논리 비약은 금지다. 속도보다 오류 없는 것이 먼저다.
- 숫자는 기록(파일)에서 확인한 것만 쓴다. 시각은 추정하지 말고 `date`나 커밋 시각을 쓴다.
- 결과를 **"최종 평가"라고 부르지 않는다.** 포스터의 숫자는 모두 "개발 배치 100벽(시작값 700300 ~ 700399) · 최종 평가 전"이다.
- 시뮬레이터 정답 좌표를 쓴 줄은 **"참값 (진단)"** 으로 표시한다(실제 로봇에서는 불가능).
- 커밋할 때마다 `git pull --rebase` → `git push`. `sim/data` · `sim/outputs` · `sim/logs`는 커밋하지 않는다.
  - 커밋 메시지 끝 줄(Co-Authored-By)은 윈도우 세션이 받은 지침을 따른다. 지침이 없으면 `Co-Authored-By: Claude <noreply@anthropic.com>`를 붙인다.
- 파일 공유는 이 비공개 저장소로만 한다. 공개 아티팩트로 올리지 않는다.
- 사용자 이름을 추측하지 않는다. 사용자 이메일은 어디에도 보내지 않는다. 토큰은 묻지도, 붙여 넣지도 않는다.
- 새 실험은 하지 않는다. 시뮬레이션을 다시 돌리지 않는다.
- 수정 금지:
  - `01_사기설/실험설계_3층벽체.md`
  - `01_사기설/평가지표_3층벽체_20261013.md`
  - `01_사기설/계획서/`
  - `sim/brick_sim/*`, `sim/collect.py`, `sim/eval_policy.py`, `sim/tools/*`
- 출력 폴더와 파일은 덮어쓰지 않는다. 새 판은 새 이름(예: 20261112f)으로 만든다. 이미 커밋된 판(c · d · e)의 파일은 지우거나 고치지 않는다.
- 스토리라인 md(`01_사기설/성능개선_스토리라인.md`)는 바뀐 내용이 생길 때마다 갱신하고 커밋한다.
- **사용자가 주는 레퍼런스 ppt는 사용자 파일이다.** 내용을 고치지 않는다. 사용자가 말하지 않는 한 커밋하지 않는다(학회 양식과 같은 취급). 설명 md에는 파일 이름과 거기서 읽은 형식만 적는다.
- 예비 그림(7.1, 3D IoU)은 pptx에 넣지 않는다.
- (우분투 쪽) 추적하지 않는 파일 두 개는 건드리지 않았다. 둘 다 저장소에 없다.
  - `대형환경_설계검토_의사결정자료_20261012.pdf`: 사용자 것이 아님

## 3. 연구 한 줄과 설정

- **한 줄**: 모방학습 정책(ACT)을 다시 학습하지 않고, 정책 밖에 규칙 기반 검측 단계를 붙였다. 각 단계를 하나씩 끄고 켜서, 3단 16장 벽의 완성과 시방(KCS 41 34 00) 합격에 각 단계가 주는 몫을 쟀다.
- **환경**
  - MuJoCo, UR10e + Robotiq 2F-140
  - 벽돌 190 × 90 × 57 mm로 3단 16자리(온장 14 · 반장 2), 줄눈 10 mm
  - 16칸 공급대. 위치가 정해진 팔레트이고, 벽돌은 칸 중심에서 ±10 mm · ±10° 흩어진다.
- **정책**: ACT. 시연 1,000벽으로 10만 스텝 학습했고(학습 seed 1000) 이후 고정했다. 실행 중에는 정답 좌표를 쓰지 않고 카메라 3대 · 관절값 · 손목 힘만 쓴다.
- **설계**: 같은 정책, 같은 100벽에서 Full과 하나씩 끈 6조건, 검측 없음, 참값 (진단)을 짝지어 비교했다.
  - 95 % 구간은 벽 단위 부트스트랩 10000번(난수 시드 0)으로 냈다.
  - 계획은 8조건 요인 설계였지만, 단계가 6개로 늘어 11-10에 역방향 제거로 바꿨다. 포스터와 구성안에 밝혔다.

## 4. 검측 단계 이름 (11-10 정리, 이 이름만 쓴다)

| 이름 | 하는 일 | 쓰는 정보 |
|---|---|---|
| G0 집기 정렬 | 정책이 공급칸 위로 내려오면 도면 중심에서 대신 집기 | 공급대 도면 · 관절값 |
| G1 집기 확인 | 1.5 cm 들어 쥐었나 판정, 못 쥐면 다시 | 손목 힘 · 집게 각도 |
| G2 놓기 전 보정 | 손 안 벽돌을 재서 설계 자리에 놓기 | 작업대 카메라 |
| G2w 넓게 받기 | G2가 넘겨받는 거리 15 → 40 cm | – |
| G3 놓은 뒤 재배치 | 놓인 벽돌을 재서 어긋나면 다시 놓기 | 작업대 카메라 |
| H 손에 든 벽돌 기준 | G2 · G3의 기준 = 쥔 순간 가장 가까운 공급칸의 벽돌 | 도면 · 관절값 |

- Full = G0 + G1 + G2 + G2w + G3 + H.
- **SDCG = G2c(놓기 확약)**: 구현해서 쟀지만 −0.09 [−1.03, +0.85]장이라 Full에서 뺐다. 겨냥한 실패(자리 6: 10 → 1벽)는 줄였지만, 힘 감지 오감지로 다른 자리에 새 실패가 생겼다.
- **VPRA**: 구현하지 않았다. Full 완성 60벽이 모두 시방 안이라 3단 벽의 실패 원인이 아니다.
- 방법론 제안 셋(VS³ · VPRA · SDCG) 가운데 Full에 들어간 것은 VS³ R4(= H) 하나뿐이다.
- **H가 큰 이유**: 정책은 한 차례에 벽돌을 여러 장 쌓는다. 10월 기록에서 G1 '쥠' 650번 중 411번이 그 차례의 벽돌이 아니었다. 기준이 틀리면 G2 · G3가 정확히 틀린 곳에 놓는다. 그래서 Full − H는 1.82장으로 검측 없음(2.00장)보다도 낮다.
- **H가 작동하는 조건**
  - 시뮬레이션: 칸 위치와 순서를 안다. 칸 간격 18 ~ 26 cm, 흩어짐 ±10 mm에서 99.5 % 맞았다. 쥔 뒤 놓을 때까지 한 장만 든다.
  - 실제 로봇(추론): 공급대를 로봇 좌표에 등록하면 된다. 오차가 칸 간격 절반보다 충분히 작으면 된다.
  - 현장(추론): 묶음 팔레트에서 순서대로 칸에 담는 공급 단계와 칸 상태 확인이 필요하다. 로봇이 옮겨 가면 다시 등록해야 한다.

## 6. 교수님 글쓰기 기준 (사용자가 붙여 준 교수님 블로그 "Is My Research Publishable?" 7편, 요약)

원문은 사용자에게 있다. 아래는 이 연구에 적용한 요지다.

- 연결 고리 **지식의 빈틈 → 연구 질문 → 연구 설계 → 결과 → 새로 안 것**이 보여야 한다. "무엇을 개발했나"가 아니라 "무엇을 알려 했나"를 쓴다.
- 기여는 빈칸 문장으로 쓴다: "선행연구는 ___을 충분히 밝히지 않았다. 본 연구는 ___로 ___을 찾았다."
- 결과를 보고 생긴 질문은 처음부터 세운 것처럼 쓰지 않는다. 이 연구의 **RQ2(검측이 효과를 내는 조건)** 는 10-28 실패 추적에서 나온 질문이라, 포스터에 **"실패 분석에서 나온 질문"** 으로 표시했다.
- 귀무가설을 기각하지 못한 것은 "효과 없음"이 아니라 **"이 배치 크기로 구별 못 함"** 이다.
- 다른 설명을 점검했는지 보인다. 이 연구에서는 세 가지를 점검했다.
  - 카메라 오차 → 참값 (진단)
  - 운(실행 간 흔들림) → Full을 3번 잼
  - 구현 오류 → G1 누락을 고친 뒤 다시 잼
- 확인한 것과 확인하지 않은 것을 나눠 주장의 범위를 밝힌다. 이 학회 독자가 왜 알아야 하는지도 쓴다.

### 7.1 예비 그림 (pptx에 넣지 않음, 11-11 사용자 결정)

- 파일: `02_KSARC2026/예비그림_3DIoU_20261111/` (그림 1장 + 설명.md). 스크립트: `sim/wall3/fig_slot_iou_20261111.py`(`WALL3_OUT` 지원)
- 내용: 조건 8개마다 벽 그림 2개다. 16자리 칸마다 색 진하기와 숫자로 두 가지를 보인다.
  - 첫 번째 벽: 그 자리를 채운 벽 수 (100벽 중)
  - 두 번째 벽: 채웠고 벽돌별 3D IoU ≥ 0.875인 벽 수
- 왜 예비인가
  - 사용자는 벽돌 하나하나의 정확도를 보고 싶었다. 그런데 시방 합격은 벽 전체 판정(16개 모두 합격 또는 모두 아님)이라 자리별로 나눌 수 없다.
  - 그래서 평가지표 md 3절의 IoU에 문턱을 뒀다. 평가지표 md는 IoU에 기준값을 두지 않았다.
  - 0.875 = 벽면 직각 6 mm 밀림 = (90 − 6) / (90 + 6). **시방 판정이 아니다.**
  - 사용자 결정: 표준 시방 기준에 근거하고 싶으므로 **포스터에는 넣지 않는다.**
- 앞서 제안한 '조건마다 16칸 벽 2개(채움 · 시방)' 그림은 폐기했다. 시방 쪽은 16칸이 모두 같은 값이 되어 의미가 없다.
- 색은 0 = 흰색 → 100 = 주황이고(사용자 지시), 조건마다 직사각형 박스로 묶었다. 이전 판(파랑)은 커밋 700c54e에 있다.

## 9. 사용자 질문에 이미 답한 것

- **"가장 큰 약점(Full 구성과 문턱을 같은 개발 배치에서 정하고 같은 배치로 잼)은 체리피킹이냐, 연구윤리상 사기냐?"** → 둘 다 아니다.
  - 개발 자료에 맞춘 설계라 값이 낙관적일 수 있다는 약점이고, 밝히면 정상적인 탐색 결과다.
  - 체리피킹(불리한 결과를 빼고 좋은 것만 보이기)은 "허용되는 수준"이 따로 없다. 결과를 왜곡하려고 데이터를 지우면 '변조'에 해당할 수 있다.
  - 선을 넘는 경우는 네 가지다.
    1. 개발 배치 결과를 "검증"이라고 부르는 것
    2. RQ2를 처음부터 세운 가설처럼 쓰는 것
    3. 음성 결과(G2c · Diffusion · 뺀 단계 · 다시 잰 값)를 빼는 것
    4. 시험 배치 결과가 나쁘다고 고쳐서 다시 돌리는 것
- **"그럼 시험 배치 말고 개발 배치 그대로 써도 되지?"** → KSARC는 된다. 조건은 세 가지다.
  - "개발 배치 100벽"이라고 표기한다.
  - 결론에 낙관적일 수 있다는 한계를 적는다.
  - "검증"이라는 말을 쓰지 않는다.
  - 나중에 논문으로 낼 때 730000번대를 쓰려면, 한 번만 고치지 않고 돌려 그대로 보고한다(사용자 허락 필요).

- 정책은 1개다(ACT, 학습 seed 1000). 시뮬레이션이고 벽 형상도 하나다.
- 시뮬레이터를 단순화했다.
  - 쥔 벽돌은 집게에 고정했다.
  - 모르타르 모델이 줄눈을 10.00 mm로 고정해 ① 가로줄눈 오차가 거의 0이다.
- 시방 6 mm를 짧은 벽에도 문언 그대로 적용했다. 판정 기준 민감도 분석(평가지표 2.7절)은 하지 않았다.
- G2와 G3가 같은 위 카메라를 쓴다.
- 시방 합격 60 %는 팀 목표 70 %에 못 미친다. 사용자: "이제와서 필수는 아니야."
- 원인을 확인하지 않은 값이 있다. 포스터에는 넣지 않았고 설명 md에만 적었다.
  - 참값 (진단)의 항목 오차가 Full보다 조금 크다(② +0.9 mm).
  - Full − G3 · Full − G2에서 한 벽씩 ① 값이 57 ~ 60 mm로 나왔다.

## 13. 양식 다듬기 절차 ("이 형식처럼 정리해놔")

### 13.1 이 말의 뜻

- **사실**: 사용자는 윈도우에서 레퍼런스 ppt를 주고 "이 형식처럼 정리해놔"라고 말하겠다고 했다. 윈도우의 일은 "ppt를 양식에 맞게 다듬는 일"이라고 했다(0.1).
- **우분투 쪽의 해석**(사용자에게 확인받지 않았다): e판의 **내용은 그대로 두고 겉모양만** 레퍼런스 ppt처럼 맞춘다. 겉모양 = 배치 · 글꼴 · 글자 크기 · 색 · 제목 띠 · 여백 · 표와 그림의 꾸밈. 레퍼런스의 글 · 숫자 · 그림은 가져오지 않는다.
- 사용자가 윈도우에서 한 말이 이 해석과 다르면 사용자 말이 먼저다.

| 레퍼런스가 어떤 파일인가 | 할 일 |
|---|---|
| 포스터 한 장 | 13.2대로 한다 |
| 학회 양식 그 자체(`ksarc-포스터 PPT 양식.pptx`) | e판은 이미 이 양식에서 만들었다. 양식의 견본 글 상자(글꼴 · 크기 · 글머리표 · 간격)와 e판을 비교해 다른 점만 맞춘다 |
| 여러 장짜리 발표 자료 | 포스터를 그 겉모양으로 꾸미라는 뜻인지, 발표 슬라이드를 새로 만들라는 뜻인지 이 문서만으로는 알 수 없다. 사용자 메시지에 더 적힌 말이 없으면 포스터에 겉모양(글꼴 · 색 · 제목 꾸밈)만 맞춘 판을 만들고, 슬라이드는 만들지 않은 채 보고에서 묻는다 |

### 13.2 순서

| 순서 | 할 일 | 설명 md에 남길 것 |
|---|---|---|
| 1 | **레퍼런스를 읽는다.** 슬라이드 크기 · 방향, 단 수와 단 너비 · 여백, 머리 영역(제목 · 저자 · 소속 · 로고), 절 제목의 모양(도형 · 색 · 글꼴 · 크기), 본문 글꼴 · 크기 · 줄 간격 · 글머리표, 표 꾸밈(머리 줄 색 · 선 · 글자 크기), 그림 · 표 제목의 위치와 번호 붙이는 법, 쓰는 색, 참고문헌 · 감사의 글의 모양. 값은 XML이나 python-pptx로 읽고, PowerPoint로 열어 눈으로도 본다 | 표 '레퍼런스 형식' |
| 2 | **e판과 비교한다.** 7절의 틀 · 글자 크기 표와 나란히 놓는다 | 표 '다른 점 → 바꿀 것 / 안 바꿀 것과 이유' |
| 3 | 방법을 고른다(13.3) | 고른 방법 |
| 4 | 새 이름으로 새 판을 만든다(13.7). e판 파일은 그대로 둔다 | – |
| 5 | PowerPoint로 열어 확인하고 고친다(13.6) | 확인 결과 |
| 6 | 내용이 바뀌지 않았는지 점검한다(13.4) | 점검 결과 |
| 7 | 설명 md · 스토리라인 · 이 문서 11절을 쓰고 커밋 → `git pull --rebase` → `git push` | – |

### 13.3 방법

| 방법 | 언제 | 어떻게 |
|---|---|---|
| (가) pptx를 직접 고친다 | 틀(단 · 순서 · 그림 크기)은 그대로이고 글꼴 · 크기 · 색 · 제목 띠 · 표 꾸밈 · 작은 위치 이동만 다를 때. 양식 파일이 없을 때 | `KSARC2026_포스터_초안_20261111e.pptx`를 새 이름으로 **복사한 뒤 복사본을** 고친다. python-pptx를 쓰면 run 단위로 고친다(`text_frame.text = …`는 서식을 지우므로 쓰지 않는다). PowerPoint에서 손으로 고쳐도 된다 |
| (나) 스크립트로 다시 만든다 | 단 수 · 단 너비 · 절의 자리 · 그림 크기가 달라질 때 | `sim/wall3/poster_ksarc_20261111e.py`를 새 파일(예: `poster_ksarc_20261112f.py`)로 복사해 고친다. e판 스크립트는 그대로 둔다. 1절 명령으로 임시 폴더에 먼저 만들어 본다 |

- (나)에서 알아 둘 것
  - 틀 상수는 `build()`의 `LX, RX, CW, HH = 1.78, 30.99, 26.6, 2.19`(왼쪽 단 x, 오른쪽 단 x, 단 너비, 절 제목 높이)와 `S1_TAG, S1_GAP, S1_ROW`(1절 꼬리표 너비 · 간격)다.
  - 글 상자 · 표 · 그림을 놓는 함수는 c판 스크립트 `poster_ksarc_20261111.py`의 `Slide.text` · `Slide.table` · `Slide.image` · `Slide.header`와 `para`다.
  - 스크립트는 양식의 도형 이름에 기댄다: '직사각형 8'(제목), 'Text Box 274'(저자), 'Text Box 275'(소속), '직사각형 18'(절 제목 견본), '직사각형 17' ~ '직사각형 28'(견본, 지움). 레퍼런스 ppt를 바탕 파일로 쓰면 이 이름들이 없을 수 있다. 그때는 (가)로 하거나 이름을 맞춰 고친다.
  - 끝에 스크립트가 넘침 · 겹침 경고를 낸다. 경고 0건이어도 PowerPoint 확인(13.6)은 따로 한다.
- **그림의 크기가 달라지면 PNG를 늘이거나 찌그러뜨리지 않는다.** 그림 함수에 새 너비 · 높이(cm)를 주어 다시 그린다. 그림 3(실험 환경)은 다시 그릴 수 없으므로 가로세로 비율(26.6 : 9.6)을 지켜 크기만 바꾼다.
- 바탕(머리 영역의 그림 · 로고 · 흰 단)은 학회 양식의 것이다. 레퍼런스의 바탕이 다르더라도 **학회 양식의 바탕은 그대로 두는 것을 기본으로 한다.** 이것은 우분투 쪽이 정한 기본값이다. 사용자가 바탕도 바꾸라고 하면 따른다.

### 13.4 바꾸면 안 되는 것 (형식을 맞추다가 내용이 달라지면 안 된다)

| 항목 | 기준 |
|---|---|
| 숫자 | 포스터의 모든 숫자. e판 설명 md의 표와 8절 |
| 글의 문장 | 형식을 맞추려고 문장을 고쳐 쓰지 않는다. 줄바꿈 · 글머리표 · 굵게 · 글자 크기 · 색은 바꿔도 된다 |
| 감사의 글 | 5절의 문장에서 한 글자도 바꾸지 않는다 |
| 절의 순서와 이름 | 1 연구 배경 및 목적 → 2 연구 방법 → 3 실험(3.1 실험 환경 세팅 · 3.2 평가 방법 · 3.3 결과) → 4 고찰 → 5 결론 → 6 감사의 글 (5절 5) |
| 표기 | "개발 배치 100벽 · 최종 평가 전", "참값 (진단)", "구별 못 함", RQ2 = "실패 분석에서 나온 질문". 10절의 말은 쓰지 않는다 |
| 그림 6장 · 표 3개 | 빼지 않는다. 표 1은 사용자가 정할 때까지 둔다(11절) |
| 결론의 한계 문장과 음성 결과(G2c · Diffusion) | 빼지 않는다(9절) |
| 5.1의 '지킬 것' | 모자이크 없음, 짧은 제목, 자리 번호 1 ~ 16, 1절 구조, 참고문헌 4편 작은 글씨, 예비 그림 넣지 않음 |

- 점검 도구: `sim/wall3/pptx_text_check_20261111.py`. 두 pptx의 슬라이드 글을 문단 단위로 비교하고, 글 속의 숫자 묶음도 따로 비교한다. 표준 라이브러리만 쓴다.
  ```powershell
  cd sim; $env:PYTHONUTF8 = "1"; $env:PYTHONPATH = "."
  python -m wall3.pptx_text_check_20261111 "..\02_KSARC2026\KSARC2026_포스터_초안_20261111e.pptx" "..\02_KSARC2026\<새 판>.pptx"
  ```

  - 이 도구는 **그림(PNG) 안의 글자를 보지 못한다.** 그림을 다시 그렸으면 눈으로 e판 그림과 비교한다.

### 13.5 자리가 모자랄 때

- **내용을 지워서 맞추지 않는다.** 무엇을 뺄지는 사용자가 정한다.
- 줄이는 순서: (1) 개체 사이 간격, (2) 그림의 높이(다시 그린다. 그림 5와 1절은 맨 나중), (3) 글자 크기.
- 레퍼런스의 글자 크기로는 e판 내용이 다 들어가지 않으면, 다 들어가는 가장 큰 크기로 맞춘 판을 만든다. 그리고 '레퍼런스 크기로 넣으려면 무엇을 빼야 하는지' 후보와 높이를 적어 사용자가 고르게 한다. 높이는 7절 표에 있다(예: 표 1 약 10 cm, 그림 4 4.0 cm, 환경 글 4.6 cm).

### 13.6 PowerPoint 확인

| 볼 것 | 왜 |
|---|---|
| 나눔고딕 · 나눔고딕 ExtraBold가 깔려 있는가 | 없으면 다른 글꼴로 바뀌어 줄바꿈과 넘침이 달라진다. 깔지 못하면 그 사실을 적고, 글꼴을 바꾸는 것은 레퍼런스가 다른 글꼴을 쓸 때만 한다 |
| 제목 · 저자 · 소속이 머리 영역 안에 있는가 | 양식의 자동 맞춤 글 상자라 스크립트가 줄 수를 어림했다 |
| 글 상자마다 글이 상자 밖으로 넘치지 않는가 | 스크립트의 넘침 점검은 글자 너비를 어림한 것이다 |
| 표가 아래 개체와 겹치지 않는가 | 표의 줄 높이는 어림한 값이다. PowerPoint는 글이 넘치면 줄을 스스로 키운다 |
| (1)(2)(3)과 – 가 제대로 보이는가 | 나눔고딕에 없는 글자를 바꿔 쓴 자리다 |
| 그림이 흐리지 않은가 | 그림은 200 ~ 300 dpi PNG다 |

- 눈으로 볼 수 없으면(사용자가 없고 화면을 볼 방법이 없을 때) PowerPoint로 슬라이드를 PNG로 내보내 그 그림을 본다. 예(시험해 보지 못했다):
  ```powershell
  $ppt = New-Object -ComObject PowerPoint.Application
  $pres = $ppt.Presentations.Open("<pptx 전체 경로>", -1, 0, 0)   # 읽기 전용(-1), 창 없이(0)
  $pres.Slides.Item(1).Export("<png 전체 경로>", "PNG", 2480, 3508)
  $pres.Close(); $ppt.Quit()
  ```
- PowerPoint가 없으면 그 사실을 적는다. 다른 프로그램(LibreOffice 등)의 렌더는 글꼴 너비가 달라 넘침 판단의 근거가 되지 못한다.
